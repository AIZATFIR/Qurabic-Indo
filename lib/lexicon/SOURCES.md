# Lexicon data sources

## Lane’s Arabic-English Lexicon

- Work: Edward William Lane, *An Arabic-English Lexicon*, London: Williams and Norgate, 1863–1893.
- Digital text: [Alpheios Lane repository](https://github.com/alpheios-project/lan), whose README credits original digitization to the Perseus Digital Library at Tufts University and corrections to the Alpheios Project.
- Alpheios identifies its digital text as [CC BY-SA 3.0 US](https://creativecommons.org/licenses/by-sa/3.0/us/).
- Local ingestion reads `data/lexicon/lane/raw/lexicon.sqlite`. Its upstream distribution is [LanesLexicon/LexiconDatabase](https://github.com/laneslexicon/LexiconDatabase), which includes a GPL-3.0 license. Conversion to JSON does not itself remove upstream obligations. Retain attribution and consult the actual upstream license files when redistributing data.
- Runtime JSON: `lib/lexicon/data/chunks/`, indexed by `manifest.json`.
- Printed part/page values are copied from the source records. Digital transcription, automatic sense extraction, and root matching may contain errors; records have not all received an independent scholarly review.

The interface preserves the transcribed English text. It no longer guesses which Latin tokens are Buckwalter: that heuristic corrupted ordinary words such as “Hence” and “English”. Arabic already encoded as Unicode receives direction and font formatting only.

## Word translations and morphology

- Primary Indonesian and English word glosses: requested at runtime from Quran.com API v4, keyed by `surah:ayah:word`. The API response does not include an individual translator attribution; do not label them Kemenag translations. Legacy JSON exports remain tracked in the repository; they are not read by application routes and Next.js tracing excludes them from deployment output. Their public-repository redistribution terms still need a documented decision. Do not remove the exports without an explicit request.
- Whole-verse Indonesian translations are a separate source (Kemenag resource 33 and fallback mirrors). English reader translation uses resource 20 (Saheeh International).
- Roots, lemmas and grammatical features: [Quranic Arabic Corpus v0.4](https://corpus.quran.com/documentation/). Its [download terms](https://corpus.quran.com/download/) say the annotation may be used in any website or app with attribution and without changing the file; its [FAQ](https://corpus.quran.com/faq.jsp) separately says downloaded annotation is for non-commercial research and describes the intended data as non-commercial. These statements leave commercial app distribution unclear. Get written clarification from the maintainers before distributing or monetizing the app; do not infer commercial permission from the GPL label alone. Indonesian class labels are interface translations, not quotations from a classical lexicon.
- Short standalone particle labels: QAC morphology tags and coordinate-matched Quran.com word glosses where available. Longer particle meanings, English fallback glosses, syntax notes, and contextual notes in `particles-dictionary.ts` are AI-assisted Qurabic drafts with no recorded scholar review. The interface labels them as such and suppresses the extended AI note when an exact Lane entry is available; the original Lane senses remain in English with their source citation. Never present AI drafts as dictionary quotations or verified classical grammar.
- Quran Foundation's current Developer Terms allow displaying API content within an app's end-user experience, but prohibit distributing raw content as a public dataset or app package. If a resource is available through Content Sync, that is the required path for an offline copy; see [Developer Terms](https://api-docs.quran.com/legal/developer-terms/) and [Content Sync](https://api-docs.quran.com/docs/tutorials/content-sync/getting-started/).

## MAQAM Quranic Corpus (English lexical-gloss fallback)

- Project and data: [CAMeL-Lab/MAQAM-Quranic-Corpus](https://github.com/CAMeL-Lab/MAQAM-Quranic-Corpus), pinned to `2e52c1354a901e998a311c94f43d14c99f467f6f`; paper: [ArabicNLP 2026](https://aclanthology.org/2026.arabicnlp-main.11/). The paper describes manual annotation of Quran word lemmas, fine-grained POS, English glosses, roots and rationality by two expert native Arabic annotators. It reports full manual validation of all morphosyntactic features on two test surahs; other morphosyntactic fields were extended computationally and may contain errors.
- The release contains 77,429 word-coordinate rows and is marked CC BY 4.0 for the dataset/original annotations; the repository's MIT code license is separate. The included derived index retains only coordinates and lexical annotations (lemma, English gloss, POS, root). It omits Quran text and other morphosyntactic fields. Attribution, license link, pinned source, and modification notice are recorded in [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md). The Quran text source has separate Tanzil attribution and terms; do not treat the repository code license as covering data.
- The corpus README says its dataset is based on Tanzil text under CC BY 3.0. Qurabic's derived index omits Quran verse text; the app's source drawer preserves this text-basis attribution separately from Quran.com, which supplies the displayed Uthmani text.
- The server index at `lib/data/maqam-glosses.sqlite` and compact offline coordinate-to-gloss index at `public/data/maqam-glosses.json` are used as an English stem-gloss fallback when a Quran.com word gloss is absent. The service worker caches the compact index with the reader shell for offline fallback. Attached prefixes or pronouns may not be included in the gloss. It is clearly labeled in both interface languages, never presented as an Indonesian translation, verse translation, tafsir, or full dictionary definition. MAQAM root and POS fields remain a distinct source and are not used to overwrite QAC assignments. Rebuild both indexes with `python3 scripts/lexicon/build-maqam-gloss-index.py <source-csv> lib/data/maqam-glosses.sqlite --public-json public/data/maqam-glosses.json`.


## Arabic Stop Words

- Source: [Arabic Stop Words by Taha Zerrouki](https://github.com/linuxscout/arabicstopwords), pinned at revision `f6018e22e02067022231d4dbda0e46b4b1b7e1e7`; release 0.9. The upstream project labels its data and software GPL-2.0. The downloaded source checksum, license, and index process are recorded in [`ARABIC-STOPWORDS-ATTRIBUTION.md`](../data/ARABIC-STOPWORDS-ATTRIBUTION.md); a copy of the source TSV and license text is included with Qurabic.
- The downloaded `stopwordsallforms.csv` contains 24,841 tab-separated records. Qurabic keeps the source rows in `lib/data/arabic-stopwords-source.tsv` and indexes them in SQLite for search. The particle view shows only rows whose upstream `type` is `حرف`; category labels, stems, prefixes, suffixes and tags remain in Arabic as source data.
- This is a morphology and classification resource, not a dictionary of meanings. Categories may be ambiguous or inconsistent; the UI labels them as source classifications and does not convert them into translations or definitions.

## Tāj al-ʿArūs root and form index

- Source project: [Arabic Roots and Derivatives by Ahmed Khorsi](https://sourceforge.net/projects/arabicrootsandderivatives/). SourceForge describes a beta MySQL database extracted from the classical dictionary *Tāj al-ʿArūs min Jawāhir al-Qāmūs*, with more than 142,000 records and 10,000 roots. Its last update is 2013-10-23.
- The downloaded `KhorsiCorpus.sql.bz2` contains 142,786 parsed form records across 11,060 distinct source roots. Qurabic includes the original compressed SQL dump at `lib/data/third-party/khorsi-taj-al-arus-source.sql.bz2` and a separate SQLite index at `lib/data/taj-al-arus-roots.sqlite`. The parser is `scripts/lexicon/build-taj-al-arus-index.py`; rebuild it with `bzip2 -dc lib/data/third-party/khorsi-taj-al-arus-source.sql.bz2 > /tmp/KhorsiCorpus.sql` followed by `python3 scripts/lexicon/build-taj-al-arus-index.py /tmp/KhorsiCorpus.sql lib/data/taj-al-arus-roots.sqlite`.
- SourceForge lists Creative Commons Attribution-ShareAlike 3.0. The SQLite index is an adapted database and is attributed under the same license; see [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md). Keep this dataset and its license distinct from Qurabic application code.
- The records contain roots, vocalized forms, unvocalized forms, and stems only. They do not include definitions, usage examples, or word classes. The project is marked beta, so this index is a discovery aid, not a complete Arabic dictionary or a scholarly verification of each form.
- A related 2017 paper by the project author Ahmed Khorsi and Abeer Alsheddi describes unsupervised Arabic morpheme extraction and identifies accuracy as a limitation: [Dependence-Based Segmentation Approach for Detecting Morpheme Boundaries](https://doi.org/10.25046/aj020314). The paper is not an evaluation of this exact 2013 dump. The source project does not document item-by-item review; Qurabic therefore does not infer meanings from the forms.
- Root matching uses exact Arabic spelling first. A normalized spelling is accepted only when it resolves to one source root; ambiguous spellings are not merged. The endpoint returns at most 40 records per request and the UI loads more on demand.

## Display boundaries

A word gloss is not a definition of its entire root. A root-entry match is not proof that each dictionary sense applies to the selected verse. Lane source language remains English and is labeled. Generated root narratives, unreviewed philosophical summaries and automatically constructed conjugations are excluded from word and root detail displays.

[QUL morphology resources](https://qul.tarteel.ai/resources/morphology) provide roots, lemmas and stems. The specific [Word root dataset](https://qul.tarteel.ai/resources/morphology/quran-word-roots/docs) documents 1,642 roots and Quran word locations (about 50,300 words with roots); it does not include dictionary definitions and excludes particles, pronouns, and demonstratives without roots. This makes it useful for corpus grouping, not for the user's requested lexical explanation of every Arabic word. QUL's FAQ says commercial use is possible subject to each resource's own terms, but the [Word root resource licence page](https://qul.tarteel.ai/resources/morphology/quran-word-roots/licence) currently says copyright information is unavailable. Until the rightsholder clarifies this dataset's terms, do not bundle or redistribute it in the Play Store app. QUL also offers [word and verse translations](https://qul.tarteel.ai/resources/translations); check each resource's licence separately before use.

## QUL morphology mapping

- QUL’s [Word root resource](https://qul.tarteel.ai/resources/morphology/quran-word-roots) offers a downloadable SQLite mapping for Quranic word roots. Its resource license page currently says copyright information is unavailable, so Qurabic does not bundle or redistribute that mapping. It maps words to roots; it does not provide classical root definitions. Reassess if the rights holder publishes terms or grants permission.
- QUL’s [Ayah Topics resource](https://qul.tarteel.ai/resources/ayah-topics/45) lists topics and ayah references. QUL attributes ontology topics to Quranic Arabic Corpus and thematic topics to The Clear Quran; the resource license page says copyright information is unavailable. We do not redistribute or present this material as Qurabic-authored tafsir without rights clarification.
- QUL currently provides direct dataset downloads; its documentation says the REST API is still in design. Downloadability is not a license grant.

## Qabas lemma links

- The per-word lemma IDs come from the QuranMorph word-level annotation dataset by Akra, Hammouda, and Jarrar (2025), which maps Quran word coordinates to Qabas lemma IDs. Source paper: [QuranMorph](https://jarrar.info/publications/AHJ25.pdf). Qabas itself is linked as an external dictionary; Qurabic does not copy its lexical definitions.
- QuranMorph is identified as CC BY 4.0 in SinaLab's resource catalog. The compact local index stores only each Quran word's Qabas lemma ID; Qurabic does not copy Qabas definitions. Links open the corresponding entry at [Qabas](https://sina.birzeit.edu/qabas).
- The source CSV was downloaded from the pinned mirror commit `079cdc74cd494ec1b35011363288d80cae047c51` of [taziksh/quran-frequencies](https://github.com/taziksh/quran-frequencies). It contained 77,429 word rows; IDs were ordered by Quran word position and checked for missing or duplicate positions before generating `data/qabas-lemma-ids.json`.
- Birzeit describes Qabas as roughly 58,000 lemmas linked to 110 dictionaries and 12 tagged corpora. Its download terms state CC BY-ND 4.0, allow commercial and non-commercial use, prohibit redistribution of a modified dataset, and require prominent attribution. Qabas also says it does not adopt dictionary gloss text because those texts remain protected by their source publishers. Qurabic therefore links to the original Qabas lemma pages instead of copying or translating their definitions. See [Qabas About and licence terms](https://sina.birzeit.edu/qabas/about).
- The public Qabas site uses an ALMA lookup endpoint, but SinaLab's resource documentation says API access requires a provided token. Qurabic must not depend on the site's embedded sample key as a production API credential; request authorized access before integrating live lookup. See [SinaLab resource documentation](https://sina.birzeit.edu/resources/index.html).
