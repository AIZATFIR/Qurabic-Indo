# Play Store readiness

Status ini mencatat bukti dari repository pada 28 November 2026. Ia bukan pernyataan bahwa aplikasi sudah siap dipublikasikan.

## Sudah disiapkan di repository

- Android `targetSdkVersion` memakai API 36. Per 28 November 2026, Google Play meminta API 36 atau lebih tinggi untuk app baru dan pembaruan reguler sejak 31 Agustus 2026. Lihat [persyaratan target API Google Play](https://developer.android.com/google/play/requirements/target-sdk).
- Build Gradle Android dibatasi ke heap 1 GiB dan satu worker untuk mengurangi tekanan memori pada mesin 8 GB. Konfigurasi ini belum diuji dengan AAB.
- `bundleRelease` menolak AAB tanpa upload signing dan `QURABIC_ANDROID_VERSION_CODE` eksplisit. `QURABIC_ANDROID_VERSION_NAME` mengatur versi yang terlihat pengguna.
- `bundleRelease` juga menolak ID contoh Google AdMob jika salah masuk ke konfigurasi produksi; ID uji tetap tersedia untuk pengembangan.
- Mixed content WebView dimatikan dan backup Android dimatikan agar data lokal tidak ikut dicadangkan otomatis.
- Capacitor memuat halaman fallback lokal berbahasa Indonesia/Inggris ketika halaman reader remote gagal dibuka; halaman ini hanya memberi status dan tombol coba lagi.
- Kebijakan privasi menjelaskan paket teks/terjemahan offline dan permintaan Quran Foundation.

## Gerbang sebelum publikasi

1. Siapkan upload keystore di penyimpanan rahasia, bukan repository; atur `QURABIC_ANDROID_KEYSTORE_PATH`, `QURABIC_ANDROID_KEYSTORE_PASSWORD`, `QURABIC_ANDROID_KEY_ALIAS`, dan `QURABIC_ANDROID_KEY_PASSWORD`. Daftarkan artefak pertama dengan Play App Signing. Baca panduan resmi [menandatangani aplikasi Android](https://developer.android.com/studio/publish/app-signing).
2. Naikkan version code setiap unggahan. Simpan salinan upload key secara aman dan buktikan pemulihannya sebelum rilis.
3. Selesaikan hak distribusi dan kewajiban source sebelum AAB dibagikan. QAC v0.4 download terms mengizinkan penggunaan app dengan atribusi, tetapi FAQ-nya menyebut data unduhan untuk riset nonkomersial; dapatkan klarifikasi tertulis untuk distribusi Play Store/monetisasi. Repository publik saat ini juga memuat ekspor glos Quran.com; Developer Terms melarang raw API data dibagikan sebagai dataset atau paket aplikasi, dan mensyaratkan Content Sync untuk offline copy bila resource tersedia di sana. QUL menawarkan glos Indonesia massal, tetapi licence resource menyebut informasi hak cipta tidak tersedia. Tinjau lisensi dan kewajiban source Lane, Arramooz, serta Arabic Stop Words, lalu tetapkan lisensi aplikasi dan siapkan source/notices yang diwajibkan. Tafsir runtime saat ini berasal dari revision `73b1d52` pada mirror `rioastamal/quran-json`; repositori menyatakan MIT, tetapi hak teks tafsir/provenansinya belum dibuktikan. Dapatkan izin tertulis atau akses resmi API LPMQ (pendaftaran, surat permohonan, survei) sebelum menyatakan sumber resmi atau mendistribusikan konten.
4. Setujui akses Quran Foundation Content, Audio, dan Search API untuk production; pasang `QF_CLIENT_ID`, `QF_CLIENT_SECRET`, `QF_ENV=production`, scope Content dan `QF_AUDIO_SCOPES=content.audio.read` dari [panduan offline Android](android-offline.md), serta `QF_SEARCH_SCOPES=search`. Jangan aktifkan klaim unduhan penuh tanpa akses dan snapshot production lengkap. Minta klarifikasi tertulis kepada pengelola Quranic Arabic Corpus mengenai penggunaan komersial/distribusi aplikasi: halaman unduh mengizinkan penggunaan aplikasi dengan atribusi, sedangkan FAQ membatasi data unduhan untuk riset nonkomersial.
   - Sebelum mengaktifkan endpoint di Vercel, buat satu WAF rule fixed-window untuk IP sumber dengan batas 30 permintaan/60 detik, mencakup `/api/content-sync`, `/api/qf/recitations`, dan `/api/search/ayah`. Setelah rule diterbitkan dan diuji, set `QURABIC_VERCEL_WAF_RATE_LIMIT=true`; tanpa attestation ini, route berbiaya tinggi menolak permintaan production dengan HTTP 503. Throttle di memori tetap menjadi lapisan tambahan. WAF mengurangi penyalahgunaan lintas instance, tetapi penghitungannya per-region sehingga trafik dari beberapa region dapat melewati ambang per-region. Vercel mengaktifkan rate limit lewat dashboard, dan usage dapat dikenai biaya: [panduan WAF Vercel](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting).
   - Katalog player produksi memakai Recitations API Quran Foundation; saat katalog belum tersedia, build produksi mempertahankan Al-Afasy lewat resource Quran Foundation. Handsfree terjemahan lisan otomatis tidak tersedia di production kecuali `NEXT_PUBLIC_HUMAN_TRANSLATION_AUDIO_RIGHTS_VERIFIED=true` diset setelah izin kedua sumber EveryAyah (English) dan Internet Archive (Indonesia) dikonfirmasi. Default-nya aman; tidak mengaktifkan flag hanya karena cakupan file tersedia. Qari EveryAyah/MP3Quran tetap untuk development. Quran Foundation mengizinkan unduhan dari host resminya atas permintaan pengguna ke storage privat dengan atribusi dan sinkronisasi yang diwajibkan. Lihat [Developer Terms Quran Foundation](https://api-docs.quran.com/legal/developer-terms/) dan [FAQ audio Quran Foundation](https://api-docs.quran.com/docs/tutorials/faq/).
   - Pemeriksaan cakupan 28 November 2026 menemukan `018001.mp3` bahasa Indonesia tidak tersedia (HTTP 404), sedangkan `002255.mp3` tersedia (HTTP 200); kode karena itu menonaktifkan handsfree terjemahan Indonesia untuk surah 3–39 dan 42. Untuk English, indeks direktori EveryAyah mencantumkan seluruh 6.236 nama file ayat Ibrahim Walk dan tidak ada ayat yang hilang; pemeriksaan dapat diulang dengan `node scripts/audio/audit-english-translation-coverage.mjs`. Ini membuktikan nama berkas tercantum di indeks, bukan bahwa semua URL selalu dapat diputar atau bahwa hak distribusinya telah diberikan. Metadata item Internet Archive yang sedang dipakai mencantumkan pengunggah `muhdayin` dan sumber `mp3-alquran.com`, tetapi kolom lisensi dan hak kosong. [eTilawa](https://etilawa.com/en/translations/indonesian/) menawarkan rekaman per surat dan menyatakan mutu/sumber berbeda menurut bahasa; halaman itu tidak mengidentifikasi narator atau lisensi. [Happy Islam](https://happyislam.life/audio/indonesian) mencakup 6.236 ayat, tetapi menyatakan suara Indonesianya dibuat dengan AI TTS. Belum ada sumber pengganti yang terverifikasi sebagai suara manusia, per ayat, dan berizin. Jangan klaim sumber audio terjemahan Indonesia siap distribusi atau mengaktifkannya untuk rilis publik sampai izin dan identitas edisi rekamannya jelas.
5. Konfigurasikan pesan privasi UMP di AdMob, lalu uji status perlu/tidak perlu consent, consent ditolak, formulir gagal dimuat, dan entry point pilihan privasi sebelum mengaktifkan iklan produksi. Pada level kode, `AdsController` meminta status UMP dan menampilkan formulir yang diwajibkan saat aplikasi dibuka; permintaan status dan formulir memakai promise terpisah yang digabung agar pemicu iklan bersamaan tidak melewati formulir. Perilaku ini belum diverifikasi di perangkat. Iklan hanya diminta jika `canRequestAds` mengizinkan. Lihat [panduan resmi UMP Android](https://developers.google.com/admob/android/privacy).
6. Isi Data safety, target audiens, rating konten, kategori, kontak dukungan, deklarasi iklan, dan tautan kebijakan di Play Console berdasarkan SDK dan alur produksi yang benar-benar aktif. Sertakan alur pencarian ayat Inggris yang meneruskan frasa kueri ke Quran.com Search API.
   - Gunakan [draf Data safety](data-safety-draft.md) sebagai inventaris awal; draf itu belum menggantikan verifikasi traffic APK atau jawaban final di Play Console.
7. Siapkan listing bahasa Indonesia dan Inggris: nama, deskripsi, ikon, screenshot ponsel, dan grafik fitur sesuai aset aktual. Jangan memakai klaim fitur yang belum diuji.
8. Bangun AAB bertanda tangan, periksa manifest dan isi bundle, lalu jalankan closed test di perangkat Android nyata: install baru online, status/navigation bars pada Android 14 dan 15/16 dengan gesture dan tiga tombol, WebView di bawah dan di atas versi 144, unduh paket, tutup paksa, buka tanpa jaringan, pindah surah/bahasa, putar dan unduh audio, hapus paket, storage penuh, upgrade aplikasi, serta pemulihan jaringan.
9. Jalankan pemeriksaan Playwright dan seluruh pemeriksaan proyek setelah pass pengembangan selesai; simpan log dan hasil per perangkat. Jangan publikasi sebelum semua status fitur, sumber data, dan batas offline cocok dengan aplikasi.
10. Verifikasi identitas akun developer dan kepemilikan nama paket di Play Console. Jika akun adalah akun personal yang dibuat setelah 13 November 2023, selesaikan closed test dengan sedikitnya 12 tester yang terus ikut selama 14 hari berturut-turut, lalu ajukan akses produksi. Lihat [persyaratan testing akun personal baru](https://support.google.com/googleplay/android-developer/answer/14151465) dan [verifikasi akun developer](https://developer.android.com/developer-verification/).
11. Saat mengirim untuk review, pastikan akun developer berwenang atas situs yang dimuat oleh Capacitor. Jelaskan fungsi khusus aplikasi yang dapat diperiksa reviewer—paket teks offline setelah sinkronisasi online pertama dan unduhan tilawah ke penyimpanan privat aplikasi—serta jangan menggambarkan instalasi baru sebagai dapat membaca offline tanpa jaringan. Google Play menilai aplikasi atas izin penggunaan situs dan fungsi/isi yang memadai; lihat [kebijakan Program Developer Google Play](https://support.google.com/googleplay/android-developer/answer/9888379) dan [batas arsitektur offline](android-offline.md#batas-arsitektur-dan-izin-play-store).

## Batas arsitektur yang masih perlu diputuskan

Capacitor saat ini membuka situs Vercel pada origin HTTPS. Service worker menyimpan shell pembaca setelah aplikasi pertama kali terbuka dengan koneksi; instalasi baru tanpa jaringan hanya dapat menampilkan halaman fallback lokal, bukan membaca konten. Uji offline harus memakai instalasi yang pernah berhasil membuka shell dan menyimpan paket. Nilai apakah pengalaman ini cukup untuk listing Android sebelum menyatakan aplikasi offline sepenuhnya.
